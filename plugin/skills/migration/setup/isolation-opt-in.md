# Isolation opt-in (live-target testing)

Followed from `configure-testing.md` when the `clone_perms` line offers the
opt-in. It is the user's own answer: never infer it.

- `prereq_status_clone_perms: failed("… No isolation_strategy is set yet. Only after the user answers …")` (only when the clone probe was refused and nothing is recorded yet) →
  - **Autonomous mode: never answer it.** Surface the line, leave isolation_strategy unset and continue setup: the project runs `clone`, so if the clone can't be created no case in the run is validated, and the question goes to the user through the Escalations tab when tests run (RUN_TESTS.md).
  - Otherwise ask **once** with `ask_user_question`, verbatim: "Your Snowflake role can't create databases, so tests can't run on a clone. Procedures can instead be tested on the live target: each case's changes are restored right after it (recovery records go to the SnowConvert metadata database), and a procedure that can't be restored that way is reported and not run. Test on the live target?" Options: "Yes, test on the live target" → `configure(isolation_strategy="auto")`; "No, keep clone" → `configure(isolation_strategy="clone")`. Never pick a default, never answer for the user. Then `configure(ensure_metadata_schema=true)` and re-parse. After yes the line is `info(…)`: tell the user once, in your own words, what it says `auto` does instead, and do not repeat the line; then continue. After no, setup continues: surface the GRANT line once (if the clone can't be created, no case in the run is validated until the role can create databases or the user opts in; a run of only read-only procedures needs no clone), and do not stop on it. If the line still offers the opt-in after the call, this scai predates the option: surface it and stop.
  - After either answer, tell the user: "You can change this any time by asking me."
- If `configure` replies that `test_config.yaml` "can't be edited in place (<reason>)": ask the user with `ask_user_question`: "May I rewrite test_config.yaml in the standard layout? Any comments in it would be lost." Yes → call the same `configure(isolation_strategy=…)` again with `isolation_strategy_rewrite=true`; No → nothing changes: surface that the strategy was not set, and continue as after "No". If it replies "can't be rewritten (<reason>)", surface the reason and continue the same way. Never set `isolation_strategy_rewrite` without that yes, and never edit `test_config.yaml` with your own file tools.
- Changing the answer any time, when the user asks (in setup or later in any conversation): `configure(isolation_strategy="auto")` to test without `CREATE DATABASE`, `configure(isolation_strategy="clone")` to stop testing on the live target (the same rewrite question applies); then re-verify. `configure` accepts only these two values; only an interactive session or the autonomous parent can set it.
